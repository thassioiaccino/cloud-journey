# Roadmap técnico

Este roadmap organiza a transição para Cloud, DevOps e Platform Engineering em etapas progressivas. Cada fase deve gerar prática documentada e, quando fizer sentido, um projeto publicável.

## 1. AWS Fundamentals — concluído

Base conceitual concluída por meio do bootcamp **Fundamentos de Cloud com AWS**, da DIO em parceria com a GFT Brasil.

O conteúdo do curso serviu como ambiente de treinamento. Projetos de AWS serão reconstruídos de forma autoral antes de entrarem no portfólio.

## 2. Linux — próxima etapa

### Conteúdos essenciais

- terminal e sistema de arquivos;
- usuários e grupos;
- permissões;
- processos;
- serviços com `systemctl`;
- logs com `journalctl`;
- gerenciamento de pacotes;
- redes básicas;
- SSH;
- variáveis de ambiente;
- Bash e automação básica;
- tarefas agendadas com `cron`.

### Critério de conclusão

Conseguir administrar um servidor Linux, diagnosticar falhas básicas e documentar uma solução prática sem copiar um roteiro pronto.

## 3. Git e GitHub

- commits e histórico;
- branches;
- merge e resolução de conflitos;
- pull requests;
- revisão de código;
- organização de Issues;
- convenções de commits;
- documentação técnica em Markdown.

## 4. Docker

- imagens e containers;
- Dockerfile;
- volumes;
- redes;
- Docker Compose;
- boas práticas e segurança básica.

## 5. Terraform

- infraestrutura como código;
- providers, resources e data sources;
- variables e outputs;
- state;
- módulos;
- provisionamento de infraestrutura em cloud.

## 6. CI/CD com GitHub Actions

- workflows;
- jobs e steps;
- secrets;
- testes e validações;
- build e deploy automatizados;
- integração com Docker e Terraform.

## 7. Kubernetes

- pods;
- deployments;
- services;
- config maps e secrets;
- ingress;
- volumes;
- observabilidade básica;
- deploy de aplicações containerizadas.

## 8. Azure

Ordem prevista:

1. fundamentos necessários do Azure;
2. preparação para o AZ-104;
3. administração prática;
4. serviços cloud-native.

## 9. Platform Engineering e SRE

- plataformas internas;
- experiência do desenvolvedor;
- observabilidade;
- confiabilidade;
- SLI, SLO e error budgets;
- automação operacional;
- self-service e golden paths.

## Regra de avanço

Uma etapa não é considerada concluída apenas pela finalização de um curso. O avanço depende de compreensão demonstrável, prática independente e documentação de qualidade.
